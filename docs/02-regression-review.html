2  Review of Linear Regression

Data for this chapter: food.csv

Data file needed

Copy food.csv into this project folder before rendering.

Multilevel models are an extension of regression, so it is worth making sure the foundation is solid before building on it. This chapter reviews simple and multiple regression, interactions, and how to present a series of models. The data come from the reading: 50 families, with information on food expenditures, income, children, and whether the family keeps a garden.

2.3 Data cleaning and coding

Three functions do the work. The first two come from dplyr, and the third from base R.

rename() changes the name of any variable in your dataset. The formula is newname = oldname. Here we are getting rid of capital letters and putting underscores between words, which makes everything easier to type and read. (Notice that the original file has a typo in one of the column names. Renaming is a good moment to quietly fix that.)

mutate() is another function I use constantly. It creates a new variable based on a transformation of an existing one. Here I take the renamed have_garden and create have_garden_fac, equal to the old variable but converted to a factor, which is what as_factor() does. Now R recognizes that “Yes” and “No” are two levels of a categorical variable, which it can use in frequency tables, regression models, and so on.

na.omit() should come with a warning label. It removes any row in a dataset with missing data, which is the same idea as listwise deletion. We use it here because the original food dataset had an extra row that was entirely missing, an error rather than a real response. But run it on a dataset that has genuine missingness and any observation missing on any variable will be dropped, including variables you were not planning to use. The nice part is that we still have food alongside food.clean, so we can always look back and see how many observations went away.

food.clean <- food %>%
  rename(.,
         food_consumption = FOODCONSUMPTION,
         family_income = FAMILYINCOME,
         num_children = NUMCHULDREN,
         have_garden = HAVEGARDEN) %>%
  mutate(.,
         have_garden_fac = as_factor(have_garden)) %>%
  na.omit()

Kids make a big difference too. For each additional child, we would expect a family to spend about $826 more per year on food. Because family_income is also in the model, we can say this holds while controlling for family income. Another way to put it: take two families with the same income, and the one with one more child is predicted to spend roughly $827 more per year.

Notice also that the estimate for family_income has not changed much, from about .06 down to .05. The adjusted R^2 rose from .56 to .60, so adding number of children explained about four percent more of the variation.

That stability in the income coefficient is itself informative. When a coefficient moves substantially after adding a variable, the two predictors are entangled and the first model was attributing to income something that belonged elsewhere. When it barely moves, as here, the two are telling you fairly separate things.

F-statistic: 26.64 on 3 and 46 DF,  p-value: 3.875e-10

Now for the fancy stuff. The first three models assumed the predictors were additive rather than interactive. That means the relationship between num_children and food expenditures is the same regardless of income, and the relationship between family_income and food is the same regardless of how many children a family has.

That is fine as a first step, but another hypothesis is that these two variables interact, or moderate one another, so that the slope of one depends on the value of the other. We specify an interaction with the : symbol, and we include both main effects as well as the interaction term. If the interaction estimate is significant, some moderation is likely happening.

In this case we do not have enough evidence to say an interaction exists. Power is likely an issue as well. We have only 50 observations, and interaction effects are notoriously underpowered, meaning you usually need a much larger sample to detect a true effect with any regularity.

That last point deserves emphasis, because it is the difference between two very different sentences. “There is no interaction” is a claim about the world. “We did not detect an interaction with 50 families” is a claim about this study. Only the second one is supported here.

2.9 Organizing your results

Last thing: let’s make the results presentable. Reporting four models one summary() at a time is unreadable, and a single comparison table is how this belongs in a paper. We named our models along the way (foodreg1, foodreg2, and so on), so collecting them is easy.

library(modelsummary)

  "Income"        = foodreg1,
  "+ Children"    = foodreg2,
  "+ Garden"      = foodreg3,
  "Interaction"   = foodreg4
)

modelsummary(

A note on stargazer

The demonstration video uses the stargazer package for this table, with an out = "test.html" option that does the same job. stargazer is no longer actively maintained and can fail with current versions of R, so this book uses modelsummary instead. The idea is identical, and modelsummary() also handles the multilevel models we fit later, which stargazer does not.

2.10 Where this goes next

Every standard error in this chapter was computed as though these 50 families were 50 independent observations, which for these data is reasonable. But a great deal of social science data is not like that. Students sit in schools, patients in hospitals, employees in firms, and repeated measures inside people. When observations come in groups, treating them as independent produces standard errors that are too small and p-values that are too optimistic.

It also raises a question ordinary regression cannot answer cleanly. A regression using everyone at once blends the comparison between two people in the same group with the comparison between two groups, and returns a single number that is neither.

The next chapter takes up both problems, using 7,185 students nested within 160 schools.
