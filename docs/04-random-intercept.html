5  Conditional Random Intercept Models

Data for this chapter: lq2002.csv

This week, we are going to use data from Gavin and Hofmann (2002), a study on organizational climate and attitudes published in Leadership Quarterly. Here, we have individual soldiers nested within companies. This is the same dataset that Garson uses in Chapter 6, so you can recreate his analysis.

The structure is the same as students within schools, which is a useful reminder that multilevel modeling is not about education specifically. Anywhere individuals are grouped, these methods apply.

Writing psych::describe() rather than just describe() is a small habit worth adopting. Several packages define a function by that name, and the package::function() form says exactly which one you mean. The variables we care about are HOSTILE (a hostility scale score, our outcome), TSIG (task significance), LEAD (leadership climate), and COMPID (company, our clustering variable). The variables beginning with G are group-level aggregates, which matter later in this chapter.

Alpha appears in the raw_alpha column. Conventional cutoffs put acceptable reliability somewhere above .70, though the right threshold depends on what the scale is for and what decisions rest on it.

The item-level output below the summary is worth reading too. The r.drop column shows how each item correlates with the total of the other items, and the “Reliability if an item is dropped” table shows what alpha would be without each one. If dropping a single item would raise alpha substantially, that item may be measuring something different from the rest.

Now, we can create a new variable, hostile, that is constructed by taking the mean of our 5 hostile items.

my.keys.list <- list(hostile = c("HOSTIL01","HOSTIL02","HOSTIL03", "HOSTIL04","HOSTIL05"))

my.scales <- scoreItems(my.keys.list, lq2002, impute = "none")

impute = "none" means a respondent missing any item gets a missing scale score rather than having the gap filled in. That is the conservative choice and the right default when you are learning; imputation is a decision that deserves its own justification.

bind_cols() glues the new column onto the original data by position, so it assumes the rows are in the same order and that nothing was dropped along the way. That holds here because scoreItems() returned one score per original row. It is worth being aware of, since a join by ID is safer whenever rows might have been reordered or filtered.

5.8.1.1 Post-estimation task: calculate ICC

Here’s a quick and easy way to get our friend the ICC!

null.ICC <- 0.05765/(0.05765 + 1.01668)
null.ICC
[1] 0.05366135

Note how much smaller this is than the ICC we found for schools and math achievement in the last chapter. That is substantively interesting rather than a problem. Soldiers’ hostility is mostly an individual matter, with companies accounting for a modest share of the variation.

A small ICC does not mean you should abandon multilevel modeling. It still corrects the standard errors, and it still lets you ask questions about company-level predictors, which is exactly where this chapter is heading.

# Conditional Random Intercept Models

**Data for this chapter:** `lq2002.csv`

This week, we are going to use data from Gavin and Hofmann (2002), a study on organizational climate and attitudes published in *Leadership Quarterly*. Here, we have individual soldiers nested within companies. This is the same dataset that Garson uses in Chapter 6, so you can recreate his analysis.

The structure is the same as students within schools, which is a useful reminder that multilevel modeling is not about education specifically. Anywhere individuals are grouped, these methods apply.

The variables we care about are `HOSTILE` (a hostility scale score, our outcome), `TSIG` (task significance), `LEAD` (leadership climate), and `COMPID` (company, our clustering variable). The variables beginning with `G` are group-level aggregates, which matter later in this chapter.

## Calculating scale scores and Cronbach's alpha

This week, we are going to get a crash course in how to calculate reliability using Cronbach's alpha. The `alpha` function in the `psych` package is a quick and easy way to calculate alpha:

```{r}
hostile_items <- lq2002 %>%
  select(., HOSTIL01,
         HOSTIL02,
         HOSTIL03,
         HOSTIL04,
         HOSTIL05)

alpha(hostile_items)
```

Alpha appears in the `raw_alpha` column. Conventional cutoffs put acceptable reliability somewhere above .70, though the right threshold depends on what the scale is for and what decisions rest on it.

The item-level output below the summary is worth reading too. The `r.drop` column shows how each item correlates with the total of the *other* items, and the "Reliability if an item is dropped" table shows what alpha would be without each one. If dropping a single item would raise alpha substantially, that item may be measuring something different from the rest.

Now, we can create a new variable, `hostile`, that is constructed by taking the mean of our 5 `hostile` items.

```{r}
my.keys.list <- list(hostile = c("HOSTIL01","HOSTIL02","HOSTIL03", "HOSTIL04","HOSTIL05"))

my.scales <- scoreItems(my.keys.list, lq2002, impute = "none")
```

`impute = "none"` means a respondent missing any item gets a missing scale score rather than having the gap filled in. That is the conservative choice and the right default when you are learning; imputation is a decision that deserves its own justification.

## Scale reliability estimates for Likert-type scales

```{r}
print(my.scales, short = FALSE)
```

## Save scored scales as new variables

```{r}
my.scores <- as_tibble(my.scales$scores)
```

## Attach the new variable to the old dataset

```{r}
lq2002.1 <- bind_cols(lq2002, my.scores)

glimpse(lq2002.1)
```

`bind_cols()` glues the new column onto the original data by position, so it assumes the rows are in the same order and that nothing was dropped along the way. That holds here because `scoreItems()` returned one score per original row. It is worth being aware of, since a join by ID is safer whenever rows might have been reordered or filtered.

## Running the multilevel models

### Step one: the null model

```{r}
model.0 <- lmer(HOSTILE ~ (1|COMPID), REML = FALSE, data = lq2002.1)

summary(model.0)
```

The `(1|COMPID)` term is what makes this multilevel. Everything else follows from it.

#### Post-estimation task: calculate ICC

Here's a quick and easy way to get our friend the ICC!

```{r}
null.ICC <- 0.05765/(0.05765 + 1.01668)
null.ICC
```

Note how much smaller this is than the ICC we found for schools and math achievement in the last chapter. That is substantively interesting rather than a problem. Soldiers' hostility is mostly an individual matter, with companies accounting for a modest share of the variation.

A small ICC does not mean you should abandon multilevel modeling. It still corrects the standard errors, and it still lets you ask questions about company-level predictors, which is exactly where this chapter is heading.

#### Using `lmerTest` to evaluate random effects
