8  Three-Level Models

Data for this chapter: projectSTAR.dta

This week, we are going to use the Kindergarten data from Project STAR, the Tennessee Class Size Experiment conducted from 1985 to 1990.

Real data often nest more than two levels deep. Students sit in classrooms, classrooms sit in schools, and each layer can contribute its own variation.

8.3.2 Create a clean dataset ready for modeling

star.clean <- projectSTAR %>%
  mutate(.,
         schoolid = gkschid,
         classid = gktchid,
         read = gktreadss,
         classtype = as_factor(gkclasstype),
         years_exp = gktyears,
         urbanicity = as_factor(gksurban),
         stu_frl = as_factor(gkfreelunch)
         ) %>%
  group_by(classid) %>% # Create a new variable, which is the average FRL by classroom:
  mutate(.,
            class_frl = mean(gkfreelunch, na.rm = TRUE) - 1
         ) %>%
  ungroup() %>%
  group_by(schoolid) %>% # Create a new variable, which is the average FRL by school:
  mutate(.,
            school_frl = mean(gkfreelunch, na.rm = TRUE) - 1
         ) %>%
  ungroup() %>%
  select(.,
         schoolid,
         classid,
         read,
         classtype,
         years_exp,
         urbanicity,
         stu_frl,
         class_frl,
         school_frl)

This is a great example of when you might “aggregate up” an individual measure to see if it is a significant predictor at level 2 or level 3. We did this in the past with the task significance measure (TSIG) and the lq2002 dataset.

The above command has two parts. First, we use the group_by command from our friend, the dplyr package, to group all responses in their groups determined by classid. This is a first step to declare that all the operations that follow are to be performed at the cluster (classroom) level. Second, we use the mutate command, which we have used before, to create new variables that are equal to the mean of the original variables. Since we just grouped by classid, this means we get the mean of the variables by classroom.

We have to get just a little fancier. Since the values of gkfreelunch are 1 for free lunch and 2 for non-free lunch, first we take the mean of that variable. Then, we subtract 1 from that value to give us the proportion of students who are non-free lunch. This gives us the new variable class_frl.

Finally, we do the same thing at the school level, grouping by schoolid, and then performing the same operation on gkfreelunch to give us school_frl, which is the proportion of students at each school who are non-free lunch.

Other than that, we are just tidying and renaming first, and then at the bottom selecting only the variables we need for the models we will run.

Why the - 1 trick works, and when it does not

The subtraction is doing something slightly clever. With a variable coded 1/2, the mean sits somewhere between 1 and 2, and subtracting 1 shifts it to sit between 0 and 1, which is a proportion. It works precisely because the coding is 1/2 with no other values.

If a variable were coded 1/2/3, or had a missing-data code like 9 mixed in, the same arithmetic would produce something meaningless that still looks like a proportion. This is why the str() step above is not optional: the recode is only correct if you have confirmed the coding first.

Notice also the two ungroup() calls. Each aggregation grouped the data, and each has to be undone before the next one groups it differently.

Worth pausing on one more thing: read here is gktreadss, the kindergarten reading scale score. This is our outcome for the whole chapter.

Two random intercept terms, joined by +, give us three levels: students within classrooms within schools.

Why this syntax works here

You may also see the nesting shorthand (1|schoolid/classid), which does the same thing when classroom IDs repeat across schools, for instance if every school numbers its classrooms 1, 2, 3.

Here that is unnecessary because gktchid is a unique teacher identifier across the whole dataset, so R can already tell classrooms apart without knowing which school they belong to. The + form is correct and simpler.

If you are ever unsure, check with n_distinct(star.clean$classid) and compare it to what you would expect. If two schools genuinely shared a classroom ID, the counts would be too low.

8.4.2 Calculate L2 ICC (classroom)

ICC.class <- 114.9/(728.2 + 169.8 + 114.9)
ICC.class
[1] 0.1134367

8.4.3 Calculate L3 ICC (school)

ICC.school <- 169.8/(728.2 + 169.8 + 114.9)
ICC.school
[1] 0.1676375

These two proportions, plus the student-level share, sum to one and describe where the variation in kindergarten reading achievement lives. Read the comparison between them rather than the absolute numbers: it speaks to whether the classroom a child lands in matters more than the school they attend, which is one of the more consequential questions in education research.

The denominator is the same in both calculations, and it is the total variance across all three levels. Getting that denominator right is where students most often slip.

# Three-Level Models

**Data for this chapter:** `projectSTAR.dta`

This week, we are going to use the Kindergarten data from Project STAR, the Tennessee Class Size Experiment conducted from 1985 to 1990.

Real data often nest more than two levels deep. Students sit in classrooms, classrooms sit in schools, and each layer can contribute its own variation.

## Part one: data exploration and management

### Use `str` to figure out the 2/1 coding scheme and variable labels

The `str` function (short for structure) will show us any variable labels or values that have been attached to a variable. You can use this to find out how variables have been coded.

```{r}
str(projectSTAR)
```

This output is long, and it is worth scrolling. Project STAR variables carry Stata labels, and the coding is not always what you would guess. Several variables here use 1/2 coding rather than the 0/1 that regression conventions assume, which is exactly the sort of thing that produces a coefficient with a baffling sign if you do not check first.

### Create a clean dataset ready for modeling

```{r}
star.clean <- projectSTAR %>%
  mutate(.,
         schoolid = gkschid,
         classid = gktchid,
         read = gktreadss,
         classtype = as_factor(gkclasstype),
         years_exp = gktyears,
         urbanicity = as_factor(gksurban),
         stu_frl = as_factor(gkfreelunch)
         ) %>%
  group_by(classid) %>% # Create a new variable, which is the average FRL by classroom:
  mutate(.,
            class_frl = mean(gkfreelunch, na.rm = TRUE) - 1
         ) %>%
  ungroup() %>%
  group_by(schoolid) %>% # Create a new variable, which is the average FRL by school:
  mutate(.,
            school_frl = mean(gkfreelunch, na.rm = TRUE) - 1
         ) %>%
  ungroup() %>%
  select(.,
         schoolid,
         classid,
         read,
         classtype,
         years_exp,
         urbanicity,
         stu_frl,
         class_frl,
         school_frl)

glimpse(star.clean)
```

This is a great example of when you might "aggregate up" an individual measure to see if it is a significant predictor at level 2 or level 3. We did this in the past with the task significance measure (`TSIG`) and the `lq2002` dataset.

The above command has two parts. First, we use the `group_by` command from our friend, the `dplyr` package, to group all responses in their groups determined by `classid`. This is a first step to declare that all the operations that follow are to be performed at the cluster (classroom) level. Second, we use the `mutate` command, which we have used before, to create new variables that are equal to the mean of the original variables. Since we just grouped by `classid`, this means we get the mean of the variables by classroom.

We have to get just a little fancier. Since the values of `gkfreelunch` are 1 for free lunch and 2 for non-free lunch, first we take the mean of that variable. Then, we subtract 1 from that value to give us the proportion of students who are non-free lunch. This gives us the new variable `class_frl`.

Finally, we do the same thing at the school level, grouping by `schoolid`, and then performing the same operation on `gkfreelunch` to give us `school_frl`, which is the proportion of students at each school who are non-free lunch.

Other than that, we are just tidying and renaming first, and then at the bottom selecting only the variables we need for the models we will run.

::: {.callout-tip}
## Why the `- 1` trick works, and when it does not

The subtraction is doing something slightly clever. With a variable coded 1/2, the mean sits somewhere between 1 and 2, and subtracting 1 shifts it to sit between 0 and 1, which is a proportion. It works precisely because the coding is 1/2 with no other values.

If a variable were coded 1/2/3, or had a missing-data code like 9 mixed in, the same arithmetic would produce something meaningless that still looks like a proportion. This is why the `str()` step above is not optional: the recode is only correct if you have confirmed the coding first.

Notice also the two `ungroup()` calls. Each aggregation grouped the data, and each has to be undone before the next one groups it differently.
:::

Worth pausing on one more thing: `read` here is `gktreadss`, the kindergarten reading scale score. This is our outcome for the whole chapter.

## Part two: the null 3-level model

### Run a null 3-level model for reading scores

```{r}
model.0 <- lmer(read ~ (1|schoolid) + (1|classid), data = star.clean)

summary(model.0)
```

Two random intercept terms, joined by `+`, give us three levels: students within classrooms within schools.

::: {.callout-note}
## Why this syntax works here

You may also see the nesting shorthand `(1|schoolid/classid)`, which does the same thing when classroom IDs repeat across schools, for instance if every school numbers its classrooms 1, 2, 3.

Here that is unnecessary because `gktchid` is a unique teacher identifier across the whole dataset, so R can already tell classrooms apart without knowing which school they belong to. The `+` form is correct and simpler.

If you are ever unsure, check with `n_distinct(star.clean$classid)` and compare it to what you would expect. If two schools genuinely shared a classroom ID, the counts would be too low.
:::
