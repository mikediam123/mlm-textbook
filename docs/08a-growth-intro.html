9  Intro to Growth Models

Data for this chapter: egmerged.dta

NoteData file needed

Copy egmerged.dta into this project folder before rendering.

This week, we go to a dataset collected as part of the US Sustaining Effects Study (Carter 1984), which attempted to assess the sustaining impacts of compensatory schooling for students over time.

The nesting changes character here. Instead of students within schools, we have observations within students: repeated measures over time. The mathematics barely changes. The interpretation changes completely, and it is worth slowing down for that shift.

Loading lmerTest after lme4 replaces lmer() with a version that adds degrees of freedom and p-values to the fixed effects in summary(). It also gives us ranova(), which we use later to test a random slope.

9.2 Part 1: two shapes for the same data

Repeated measures data can be stored in two ways. In wide format, each person gets one row, and each measurement occasion gets its own column. In long format, each person gets one row per occasion, and time is stored in its own variable.

A small example makes the difference concrete. Here are three made-up students, measured in up to three years, stored wide:

toy.wide <- tibble(
  childid    = c(1, 2, 3),
  math_year1 = c(-2.1, -3.0, -2.6),
  math_year2 = c(-1.2, -2.4, -1.9),
  math_year3 = c(-0.5, -1.6, NA)
)

toy.wide
# A tibble: 3 × 4
  childid math_year1 math_year2 math_year3
    <dbl>      <dbl>      <dbl>      <dbl>
1       1       -2.1       -1.2       -0.5
2       2       -3         -2.4       -1.6
3       3       -2.6       -1.9       NA

Student 3 was not measured in year 3, so that cell is empty. Now the same information, stored long:

toy.long <- toy.wide %>%
  pivot_longer(.,
               cols = starts_with("math"),
               names_to = "year",
               names_prefix = "math_year",
               names_transform = list(year = as.numeric),
               values_to = "math",
               values_drop_na = TRUE)

toy.long
# A tibble: 8 × 3
  childid  year  math
    <dbl> <dbl> <dbl>
1       1     1  -2.1
2       1     2  -1.2
3       1     3  -0.5
4       2     1  -3  
5       2     2  -2.4
6       2     3  -1.6
7       3     1  -2.6
8       3     2  -1.9

pivot_longer() stacks the three math columns into one. cols selects which columns to stack. names_to names the new variable that holds the old column names, and names_prefix strips the “math_year” text so only the year number is left. Column names are always text, so names_transform converts year to a number we can fit a slope to. values_to names the variable that holds the scores. Finally, values_drop_na = TRUE drops the empty cell, so Student 3 simply has two rows instead of three.

pivot_wider() reverses the operation:

toy.long %>%
  pivot_wider(.,
              id_cols = childid,
              names_from = year,
              names_prefix = "math_year",
              values_from = math)
# A tibble: 3 × 4
  childid math_year1 math_year2 math_year3
    <dbl>      <dbl>      <dbl>      <dbl>
1       1       -2.1       -1.2       -0.5
2       2       -3         -2.4       -1.6
3       3       -2.6       -1.9       NA

id_cols identifies a row in the wide data. names_from supplies the new column names, and values_from fills the cells. Student 3’s missing year comes back as NA.

9.2.1 Why growth models need long data

Growth models require long format, for three reasons.

  1. Each row is one level-1 unit. In a growth model, the level-1 units are measurement occasions. Long format gives each occasion its own row, just as earlier chapters gave each student their own row.
  2. Time becomes a variable. In wide data, time is hidden in the column names. In long data, year is a variable we can put in the model, center, and give a slope.
  3. Unbalanced data are handled naturally. Students measured three times and students measured six times sit side by side. Nobody is dropped for missing a year. This is one of the main advantages of the multilevel approach to change over older repeated measures methods.

Wide data still have uses. Many descriptive tables and correlation matrices want one row per person, and wide data make missing waves easy to see, as we do below.

These data are already long. There is one row per student per year. A student who was measured six times appears in six rows, with their time-invariant characteristics repeated on each one.

9.3.2 Create our analysis variables

egmerged.clean <- egmerged %>%
  mutate(.,
         year0 = year - 1)

That line is doing more work than it appears to. The intercept in any regression is the predicted outcome when every predictor equals zero, including time. Left as year running from 1, the intercept would describe a measurement occasion before the study began. Recoded so the first wave is 0, the intercept becomes the predicted score at the start of the study (kindergarten, for nearly all students), which is a quantity you can defend in print.

9.3.5 Look at the trajectories

set.seed(664)
sample.ids <- sample(unique(egmerged.clean$childid), 30)

egmerged.clean %>%
  filter(childid %in% sample.ids) %>%
  ggplot(., mapping = aes(x = year0, y = math, group = childid)) +
  geom_line(alpha = .50) +
  geom_point(alpha = .50) +
  labs(title = "Observed Math Scores Over Time",
       caption = "Notes. Random sample of 30 students in the Sustaining Effects Study (Carter, 1984). Year 0 = Kindergarten.") +
  ylab("Math Score") +
  xlab("Year")

This is often called a spaghetti plot. Each line is one child. The group = childid argument tells ggplot which points belong together, and it only works because the data are long: one row per occasion, with an ID linking each child’s rows.

Look at two things before modeling. First, nearly every line rises, so some kind of growth term belongs in the model. Second, the lines start at different heights and climb at somewhat different angles. Different heights suggest a random intercept. Different angles suggest a random slope. We test both ideas below.

9.4.4 Calculate the GROWTH ICC

performance::icc(model.null.growth)
# Intraclass Correlation Coefficient

    Adjusted ICC: 0.714
  Unadjusted ICC: 0.377

icc() reports two values once the model has a fixed effect. The adjusted ICC uses only the variance components, which matches the hand calculation from earlier chapters. The unadjusted ICC also counts the variance explained by the fixed effects. Report the adjusted value.

Compare the residual variances in the two models: roughly 1.52 in the null model, roughly 0.35 once time is included. That is a large drop, and the reason is worth stating carefully.

In the first model, “within-student variance” lumped together everything that made a child’s scores differ across occasions, including the fact that they were growing. In the second, growth has been pulled out into a fixed effect, so the residual now represents deviation from a student’s own trajectory rather than deviation from their own average.

This is the conceptual heart of growth modeling. The level-1 units are occasions, and what varies at level 1 is how far a particular measurement sits from where the model expected that student to be at that time.

female is coded 1 for girls and 0 for boys. It is measured once per student, so it is a level-2 predictor even though it appears on every row of the long dataset. Entered on its own, it can shift a student’s whole trajectory up or down, but it cannot change the slope. This coefficient describes a difference in where students start, not a difference in how fast they grow. Everything so far assumes a single common growth rate.

Here, the coefficient for female is small and not statistically significant. In this sample, girls and boys appear to start at about the same level.

Interacting a level-2 characteristic with time is how we ask whether trajectories diverge. The main effect of female is a difference in starting point; the interaction is a difference in slope. Those are separate claims, and conflating them is one of the most common errors in write-ups of growth models.

A gap that is constant over time and a gap that widens over time call for very different responses, and only the interaction can tell them apart. Here, the interaction is also small and not statistically significant. We did not detect a difference in growth rates between girls and boys in this sample. A null interaction is still informative: it is what parallel trajectories look like in the output.

Note the difference from the interaction. The interaction asked whether girls and boys, as groups, grow at different rates. The random slope asks whether individual students do, without trying to explain why. Picture two children with identical kindergarten scores: one climbs steadily, the other plateaus. A random intercept model cannot tell them apart. This one can.

The control argument changes the optimizer, the algorithm lmer() uses to search for the best estimates. With the default optimizer, this model returns a “failed to converge” warning. Switching to bobyqa is a common first step when that happens. The estimates are essentially identical either way, which suggests the original warning was a false alarm. Still, a convergence warning should never simply be ignored, and checking a second optimizer is a quick way to see whether it matters.

The two ideas also work together. The random slope variance in model.3 is the variation in growth rates that remains after accounting for gender. If a level-2 predictor explains part of why children grow at different rates, adding its interaction with time reduces that variance. Here, the slope variance barely changes with or without the interaction, which fits with the null interaction above.

9.5.4 Should we keep that random slope for time? Use ranova to test

ranova(model.3)
ANOVA-like table for random-effects: Single term deletions

Model:
math ~ year0 + female + year0:female + (year0 | childid)
                           npar  logLik   AIC    LRT Df Pr(>Chisq)    
<none>                        8 -8386.2 16788                         
year0 in (year0 | childid)    6 -8527.5 17067 282.57  2  < 2.2e-16 ***
---

ranova() refits the model with each random slope removed and compares the two with a likelihood ratio test. The row for year0 in (year0 | childid) tests whether letting slopes vary across children improves fit. Note that removing the random slope removes two parameters (the slope variance and its covariance with the intercept), which is why the test has 2 degrees of freedom.

Taken together, these results suggest that children differ a good deal in how fast they grow, but gender does not explain those differences in this sample.

9.6 Part 5: visualize the results

9.6.1 Predicted trajectories for girls and boys

prediction.grid <- expand_grid(year0 = 0:5,
                               female = c(0, 1)) %>%
  mutate(.,
         gender = if_else(female == 1, "Girls", "Boys"))

prediction.grid$predicted <- predict(model.3, newdata = prediction.grid, re.form = NA)

ggplot(data = prediction.grid, mapping = aes(x = year0, y = predicted, color = gender)) +
  geom_line(linewidth = 1) +
  labs(title = "Predicted Change in Math Scores Over Time",
       subtitle = "Girls Compared With Boys",
       color = NULL,
       caption = "Notes. N = 1,721 students in the Sustaining Effects Study (Carter, 1984). Year 0 = Kindergarten.") +
  ylab("Predicted Math Score") +
  xlab("Year")

expand_grid() builds every combination of the values we supply: six years crossed with the two values of female. The result is a small long dataset, one row per year per group. predict() with re.form = NA then returns the fixed-effects prediction for each row, which is the average trajectory for each group. The gender variable just gives the lines readable labels.

The two lines are the interaction made visible. If they diverged, the gap would be widening over time. Here they nearly overlap from start to finish, which is the picture of a small main effect and a small interaction. Reading the coefficient tells you the direction; seeing the plot tells you how much it matters.

9.6.2 Random slopes for a sample of 50 students

predicted.vals <- broom.mixed::augment(model.3)

set.seed(664)
sample.ids50 <- sample(unique(predicted.vals$childid), 50)

predicted.vals %>%
  filter(childid %in% sample.ids50) %>%
  ggplot(., mapping = aes(x = year0, y = .fitted, color = as_factor(childid))) +
  geom_point(alpha = .50) +
  geom_line() +
  labs(title = "Predicted Change in Math Scores Over Time",
       caption = "Notes. Random sample of 50 students in the Sustaining Effects Study (Carter, 1984). Year 0 = Kindergarten.") +
  ylab("Predicted Math Score") +
  xlab("Year") +
  theme(legend.position = "none")

augment() returns the original data plus fitted values, residuals, and related quantities in a tidy data frame. For an lmer model, the fitted values include each child’s own random effects, not just the average trajectory, which is what lets this plot show individual variation.

This is the picture the random slope variance is summarizing. Each line is one child. The spread of their angles is the slope variance, and seeing it directly may be more convincing than any number in the output. Compare it with the spaghetti plot of observed scores in Part 2: the model has smoothed each child’s ups and downs into a straight line.

# Intro to Growth Models

**Data for this chapter:** `egmerged.dta`

::: {.callout-note}
## Data file needed
Copy `egmerged.dta` into this project folder before rendering.
:::

This week, we go to a dataset collected as part of the US Sustaining Effects Study (Carter 1984), which attempted to assess the sustaining impacts of compensatory schooling for students over time.

The nesting changes character here. Instead of students within schools, we have *observations within students*: repeated measures over time. The mathematics barely changes. The interpretation changes completely, and it is worth slowing down for that shift.

## Load in our MVP packages

```{r}
#| label: setup

suppressPackageStartupMessages(library(tidyverse))
library(lme4)
library(lmerTest)
```

Loading `lmerTest` after `lme4` replaces `lmer()` with a version that adds degrees of freedom and *p*-values to the fixed effects in `summary()`. It also gives us `ranova()`, which we use later to test a random slope.

## Part 1: two shapes for the same data

Repeated measures data can be stored in two ways. In **wide** format, each person gets one row, and each measurement occasion gets its own column. In **long** format, each person gets one row *per occasion*, and time is stored in its own variable.

A small example makes the difference concrete. Here are three made-up students, measured in up to three years, stored wide:

```{r}
toy.wide <- tibble(
  childid    = c(1, 2, 3),
  math_year1 = c(-2.1, -3.0, -2.6),
  math_year2 = c(-1.2, -2.4, -1.9),
  math_year3 = c(-0.5, -1.6, NA)
)

toy.wide
```

Student 3 was not measured in year 3, so that cell is empty. Now the same information, stored long:

```{r}
toy.long <- toy.wide %>%
  pivot_longer(.,
               cols = starts_with("math"),
               names_to = "year",
               names_prefix = "math_year",
               names_transform = list(year = as.numeric),
               values_to = "math",
               values_drop_na = TRUE)

toy.long
```

`pivot_longer()` stacks the three math columns into one. `cols` selects which columns to stack. `names_to` names the new variable that holds the old column names, and `names_prefix` strips the "math_year" text so only the year number is left. Column names are always text, so `names_transform` converts `year` to a number we can fit a slope to. `values_to` names the variable that holds the scores. Finally, `values_drop_na = TRUE` drops the empty cell, so Student 3 simply has two rows instead of three.

`pivot_wider()` reverses the operation:

```{r}
toy.long %>%
  pivot_wider(.,
              id_cols = childid,
              names_from = year,
              names_prefix = "math_year",
              values_from = math)
```

`id_cols` identifies a row in the wide data. `names_from` supplies the new column names, and `values_from` fills the cells. Student 3's missing year comes back as `NA`.

### Why growth models need long data

Growth models require long format, for three reasons.

1. **Each row is one level-1 unit.** In a growth model, the level-1 units are measurement occasions. Long format gives each occasion its own row, just as earlier chapters gave each student their own row.
2. **Time becomes a variable.** In wide data, time is hidden in the column names. In long data, `year` is a variable we can put in the model, center, and give a slope.
3. **Unbalanced data are handled naturally.** Students measured three times and students measured six times sit side by side. Nobody is dropped for missing a year. This is one of the main advantages of the multilevel approach to change over older repeated measures methods.

Wide data still have uses. Many descriptive tables and correlation matrices want one row per person, and wide data make missing waves easy to see, as we do below.

## Part 2: load and explore the data

### Load in the data

```{r}
egmerged <- haven::read_dta("egmerged.dta")

glimpse(egmerged)
```

These data are already long. There is one row per student *per year*. A student who was measured six times appears in six rows, with their time-invariant characteristics repeated on each one.

### Create our analysis variables

```{r}
egmerged.clean <- egmerged %>%
  mutate(.,
         year0 = year - 1)
```

That line is doing more work than it appears to. The intercept in any regression is the predicted outcome when every predictor equals zero, including time. Left as `year` running from 1, the intercept would describe a measurement occasion before the study began. Recoded so the first wave is 0, the intercept becomes the predicted score at the start of the study (kindergarten, for nearly all students), which is a quantity you can defend in print.

### How many times was each student measured?

```{r}
egmerged.clean %>%
  count(childid, name = "waves") %>%
  count(waves, name = "n_students")
```

This is the first check to run on any long dataset. The inner `count()` tallies rows per student; the outer one tallies students by their number of rows. Here, most students contribute between three and five occasions, and very few contribute all six.

### Use `pivot_wider` to see which years are missing

```{r}
egmerged.wide <- egmerged.clean %>%
  pivot_wider(.,
              id_cols = childid,
              names_from = year,
              names_prefix = "math_year",
              names_sort = TRUE,
              values_from = math)

egmerged.wide %>%
  summarize(across(starts_with("math"), ~ sum(!is.na(.x))))
```

`names_sort = TRUE` puts the new columns in year order; otherwise they appear in whatever order the years first show up in the data. The wide version has one row per student, so counting non-missing cells in each column shows how many students were measured in each year. Very few students were tested in year 1, which matters for interpretation. Our intercept describes the start of the study, and the data are thinnest exactly there.

### Look at the trajectories

```{r}
#| label: fig-spaghetti
#| fig-cap: "Observed math trajectories for a random sample of 30 students."

set.seed(664)
sample.ids <- sample(unique(egmerged.clean$childid), 30)

egmerged.clean %>%
  filter(childid %in% sample.ids) %>%
  ggplot(., mapping = aes(x = year0, y = math, group = childid)) +
  geom_line(alpha = .50) +
  geom_point(alpha = .50) +
  labs(title = "Observed Math Scores Over Time",
       caption = "Notes. Random sample of 30 students in the Sustaining Effects Study (Carter, 1984). Year 0 = Kindergarten.") +
  ylab("Math Score") +
  xlab("Year")
```

This is often called a spaghetti plot. Each line is one child. The `group = childid` argument tells `ggplot` which points belong together, and it only works because the data are long: one row per occasion, with an ID linking each child's rows.

Look at two things before modeling. First, nearly every line rises, so some kind of growth term belongs in the model. Second, the lines start at different heights and climb at somewhat different angles. Different heights suggest a random intercept. Different angles suggest a random slope. We test both ideas below.

## Part 3: from a null model to a growth model

### Run a regular null model for math scores

```{r}
model.null <- lmer(math ~ (1|childid), data = egmerged.clean)

summary(model.null)
```

### Calculate the ICC

```{r}
performance::icc(model.null)
```

Interpret this the way you would any ICC, but notice what the levels now mean. The between-cluster variance is between *students*, and the within-cluster variance is within a student across occasions. So the ICC answers: how much of the variation in math scores reflects stable differences between children, versus change within a child over time?

### Now, run a GROWTH null model for math scores (with year included)

```{r}
model.null.growth <- lmer(math ~ year0 + (1|childid), data = egmerged.clean)

summary(model.null.growth)
```

### Calculate the GROWTH ICC

```{r}
performance::icc(model.null.growth)
```

`icc()` reports two values once the model has a fixed effect. The **adjusted ICC** uses only the variance components, which matches the hand calculation from earlier chapters. The **unadjusted ICC** also counts the variance explained by the fixed effects. Report the adjusted value.

Compare the residual variances in the two models: roughly 1.52 in the null model, roughly 0.35 once time is included. That is a large drop, and the reason is worth stating carefully.

In the first model, "within-student variance" lumped together everything that made a child's scores differ across occasions, including the fact that they were *growing*. In the second, growth has been pulled out into a fixed effect, so the residual now represents deviation from a student's own trajectory rather than deviation from their own average.

This is the conceptual heart of growth modeling. The level-1 units are occasions, and what varies at level 1 is how far a particular measurement sits from where the model expected that student to be at that time.

## Part 4: adding predictors

### Add a predictor for the intercept: female

```{r}
model.1 <- lmer(math ~ year0 + female + (1|childid), data = egmerged.clean)

summary(model.1)
```

`female` is coded 1 for girls and 0 for boys. It is measured once per student, so it is a level-2 predictor even though it appears on every row of the long dataset. Entered on its own, it can shift a student's whole trajectory up or down, but it cannot change the slope. This coefficient describes a difference in where students *start*, not a difference in how fast they grow. Everything so far assumes a single common growth rate.

Here, the coefficient for `female` is small and not statistically significant. In this sample, girls and boys appear to start at about the same level.

### Do growth rates differ for girls and boys? This is an interaction effect

```{r}
model.2 <- lmer(math ~ year0 + female + year0:female + (1|childid), data = egmerged.clean)

summary(model.2)
```

Interacting a level-2 characteristic with time is how we ask whether trajectories diverge. The main effect of `female` is a difference in starting point; the interaction is a difference in slope. Those are separate claims, and conflating them is one of the most common errors in write-ups of growth models.

A gap that is constant over time and a gap that widens over time call for very different responses, and only the interaction can tell them apart. Here, the interaction is also small and not statistically significant. We did not detect a difference in growth rates between girls and boys in this sample. A null interaction is still informative: it is what parallel trajectories look like in the output.

### Add a random slope for year at the child level

```{r}
model.3 <- lmer(math ~ year0 + female + year0:female + (year0|childid),
                data = egmerged.clean,
                control = lmerControl(optimizer = "bobyqa"))

summary(model.3)
```

Note the difference from the interaction. The interaction asked whether girls and boys, as *groups*, grow at different rates. The random slope asks whether *individual* students do, without trying to explain why. Picture two children with identical kindergarten scores: one climbs steadily, the other plateaus. A random intercept model cannot tell them apart. This one can.

The `control` argument changes the optimizer, the algorithm `lmer()` uses to search for the best estimates. With the default optimizer, this model returns a "failed to converge" warning. Switching to `bobyqa` is a common first step when that happens. The estimates are essentially identical either way, which suggests the original warning was a false alarm. Still, a convergence warning should never simply be ignored, and checking a second optimizer is a quick way to see whether it matters.

The two ideas also work together. The random slope variance in `model.3` is the variation in growth rates that remains *after* accounting for gender. If a level-2 predictor explains part of why children grow at different rates, adding its interaction with time reduces that variance. Here, the slope variance barely changes with or without the interaction, which fits with the null interaction above.

### Should we keep that random slope for time? Use `ranova` to test

```{r}
ranova(model.3)
```

`ranova()` refits the model with each random slope removed and compares the two with a likelihood ratio test. The row for `year0 in (year0 | childid)` tests whether letting slopes vary across children improves fit. Note that removing the random slope removes two parameters (the slope variance and its covariance with the intercept), which is why the test has 2 degrees of freedom.

Taken together, these results suggest that children differ a good deal in how fast they grow, but gender does not explain those differences in this sample.

### Predicted trajectories for girls and boys

```{r}
#| label: fig-predicted

prediction.grid <- expand_grid(year0 = 0:5,
                               female = c(0, 1)) %>%

ggplot(data = prediction.grid, mapping = aes(x = year0, y = predicted, color = gender)) +

```

`expand_grid()` builds every combination of the values we supply: six years crossed with the two values of `female`. The result is a small long dataset, one row per year per group. `predict()` with `re.form = NA` then returns the fixed-effects prediction for each row, which is the average trajectory for each group. The `gender` variable just gives the lines readable labels.

The two lines are the interaction made visible. If they diverged, the gap would be widening over time. Here they nearly overlap from start to finish, which is the picture of a small main effect and a small interaction. Reading the coefficient tells you the direction; seeing the plot tells you how much it matters.

### Random slopes for a sample of 50 students

```{r}

predicted.vals <- broom.mixed::augment(model.3)

```

`augment()` returns the original data plus fitted values, residuals, and related quantities in a tidy data frame. For an `lmer` model, the fitted values include each child's own random effects, not just the average trajectory, which is what lets this plot show individual variation.

This is the picture the random slope variance is summarizing. Each line is one child. The spread of their angles *is* the slope variance, and seeing it directly may be more convincing than any number in the output. Compare it with the spaghetti plot of observed scores in Part 2: the model has smoothed each child's ups and downs into a straight line.
